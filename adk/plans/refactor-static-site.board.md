## 사람
### 목표
빌드 도구 없는 정적 GitHub Pages 사이트의 구조를 정리합니다. 화면 디자인과 기능 동작은 바꾸지 않습니다.
- `game.js`와 `guestbook.js`에 각자 있는 Supabase 설정과 공통 유틸을 한 곳(`common.js`)으로 모읍니다.
- 한 파일에 몰려 있는 `game.js`(1,077줄)와 `style.css`(2,153줄)를 기능별 파일로 나눕니다.
- 방명록·게임 코드를 전역 스코프에서 분리해, 브라우저 콘솔에서 내부 함수와 변수에 접근할 수 없게 합니다.
- 쓰지 않는 파일을 정리하고, README와 맵을 실제 저장소와 맞춥니다.

### 결정과 이유
- **D1. 범위 — A: 구조만 정리합니다.** 동작과 디자인을 그대로 두어야 리팩토링 전후를 비교해 검증할 수 있기 때문입니다.
- **D2. 도구 — A: 빌드 없는 정적 사이트를 유지합니다.** 지금처럼 파일을 GitHub Pages에 그대로 올려 배포할 수 있기 때문입니다.
- **D3. 삭제 — A: 미사용 이미지 3개와 Python 골격을 모두 지웁니다.** 사이트 어디에서도 참조하지 않는 파일들입니다. 삭제 전에 참조가 없는지 다시 검색하고, 참조가 발견된 파일은 지우지 않습니다.
- **D4. 분할 방식 — A: 브라우저 ES 모듈로 나눕니다.** 빌드 없이 파일을 나누면서 전역 은닉도 유지할 수 있기 때문입니다. 대신 로컬에서는 파일을 바로 열 수 없고 정적 서버로 열어야 확인할 수 있습니다.
- **D5. 유틸 통합 — A: 공통 함수에 옵션을 두어 페이지마다 지금 동작을 그대로 유지합니다.** 버튼 로딩 모양과 7일이 지난 날짜 표시가 게임과 방명록에서 서로 다르기 때문입니다. 두 페이지의 토스트도 모양이 달라서 합치지 않습니다.

### 현재 작업
승인이 끝났고, 아래 다섯 단계를 순서대로 진행할 예정입니다. 실행은 중계 claude-opus-5-5(medium), 구현 gpt-6.1-sol(medium)이 맡습니다. 아직 구현은 시작하지 않았습니다.
1. `common.js`를 새로 만들고 방명록의 중복 코드를 공통 모듈 호출로 바꾼 뒤 ES 모듈로 전환합니다. (standard)
2. 게임 코드의 중복을 제거하고 보드·입력·사운드·랭킹·UI 모듈(`game/`)로 나눕니다. (complex)
3. `style.css`를 공통 스타일과 페이지별 CSS(`css/`)로 나누고, 쓰지 않는 규칙과 불필요한 `!important`를 정리합니다. (standard)
4. 미사용 이미지 3개와 Python 골격 파일을 삭제합니다. (mechanical)
5. README의 버전·구조·프로젝트 수를 실제와 맞추고, 맵에 파일 행을 채웁니다. (small)

각 단계마다 구문 검사를 하고 로컬 정적 서버에서 동작과 화면이 이전과 같은지 확인합니다. Supabase 키 값과 데이터 계약은 바꾸지 않습니다.
