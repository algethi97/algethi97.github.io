## 사람
### 목표
단계 1에서 만든 `common.js`와 방명록 모듈화를 이어받아, 빌드 도구 없는 정적 GitHub Pages 사이트의 나머지 구조를 정리합니다. 화면 디자인과 기능 동작은 바꾸지 않습니다.
- `game.js`의 Supabase 설정, 클라이언트 생성, 상대 시간, 버튼 로딩 중복을 `common.js` 호출로 바꾸고, 게임 코드를 `game/` 아래 보드·입력·사운드·랭킹·UI 모듈로 나눕니다.
- `style.css`를 공통 스타일과 페이지별 CSS(`css/`)로 나누고, 쓰지 않는 규칙과 불필요한 `!important`를 정리합니다.
- 미사용 이미지 3개와 Python 골격 파일을 삭제합니다.
- README와 `adk/mapping.adesk.md`를 실제 저장소와 맞춥니다.

### 결정과 이유
- **D1. 범위 — A: 구조만 정리합니다.** 동작과 디자인을 그대로 두어야 리팩토링 전후를 비교해 검증할 수 있기 때문입니다.
- **D2. 도구 — A: 빌드 없는 정적 사이트를 유지합니다.** 파일을 GitHub Pages에 그대로 올려 배포할 수 있기 때문입니다.
- **D3. 삭제 — A: 미사용 이미지 3개와 Python 골격을 모두 지웁니다.** 삭제 전에 참조가 없는지 다시 검색하고, 참조가 발견된 파일은 지우지 않습니다.
- **D4. 분할 방식 — A: 브라우저 ES 모듈로 나눕니다.** 빌드 없이 파일을 나누면서 전역 은닉도 유지할 수 있기 때문입니다. 대신 로컬에서는 정적 서버로 열어 확인해야 합니다.
- **D5. 유틸 통합 — A: 공통 함수에 옵션을 두어 게임·방명록의 현재 동작을 각각 유지합니다.** 버튼 로딩 모양과 7일 이후 날짜 표시가 서로 다르고, 두 페이지의 토스트도 모양이 달라 합치지 않습니다.
